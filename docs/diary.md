# The diary format

`collie capture` turns a dictated sentence into one of two things: a calendar event, or a line in a
diary. This page fixes what that diary looks like on disk.

It is written down because the format is the part that is expensive to change later. Files
accumulate: a convention you alter in month three has to be migrated, and anything that read them —
an editor, a script, a weekly review — breaks quietly. `tests/test_diary_format.py` asserts what is
below against what `capture` actually writes, so this page cannot drift into being a description of
what someone once intended.

## Where

```
$CAPTURE_DIR/                      # default ~/Documents/CollieCapture
  inbox.md                         # every utterance, in the order it arrived
  diary/
    2026/
      2026-08-15.md                # one file per day
  assets/
    2026-08-15-1.jpg               # pictures and audio live beside the text, never inside it
```

`CAPTURE_DIR` is a setting. Point it inside an Obsidian vault, iCloud Drive or a git repo and that
tool's sync, search and rendering come for free — which is most of the reason the format is plain.

## The day file

```markdown
# 2026-08-15 周六

- **09:12** 把签名那件事解决了 #vocalcode
- **11:40** 明天下午三点和 kobe 开个会　→ 📅 和 kobe 开个会(08-16 15:00)
- **14:02** 也许该把日记的格式定下来 ⚠️待定
```

- One heading, the date and its weekday, written once when the file is created.
- One line per capture, `- **HH:MM** ` then **the sentence as it was said**. Not a cleaned-up
  version: what you actually said is the only part nothing else can reconstruct.
- An event line keeps the sentence and appends `　→ 📅 <title>(<when>)`. The event itself lives in
  your calendar; this is the trace that it happened, so a day reads as a day.
- `⚠️待定` marks a capture that sounded like scheduling but carried no usable time. It is a flag for
  a person, not a state machine — nothing consumes it.
- Tags are just `#word` inside the sentence. No parser, no index, no front matter: `grep -r '#vocalcode'`
  is the feature, and it works in every editor ever written.

## inbox.md

```markdown
- 2026-08-15 09:12 [diary] 把签名那件事解决了 #vocalcode
- 2026-08-15 11:40 [event] 明天下午三点和 kobe 开个会 → 和 kobe 开个会 @ 08-16 15:00
- 2026-08-15 14:02 [review] 也许该把日记的格式定下来
```

Every utterance lands here **before** it is routed, so a misclassification costs you a wrong line in
the diary and never the sentence itself. `[event]` / `[diary]` / `[review]` is how it was classified.

## Rules that are load-bearing

1. **Append-only.** Nothing rewrites a past line. A file you can only add to is a file two processes
   can share, a file `git diff` reads usefully, and a file no bug can quietly rewrite.
2. **No front matter, no HTML, no base64.** The moment the text needs a parser to be readable it has
   stopped being yours and started being an application's storage.
3. **Assets are files.** `![](../assets/2026-08-15-1.jpg)` — standard markdown, real files, visible
   in Finder.
4. **The record is on the computer.** The phone holds only what it has not delivered yet; the cloud
   mailbox is transit and forgets. Two stores that both claim to be the diary is how they diverge.
5. **Machine-written entries say so.** A weekly review generated by a dog is a different kind of
   thing from something you said, and a reader must be able to tell without guessing:

   ```markdown
   ## 周回顾 · 2026-W33 · 由 Rowan 生成
   ```

   It goes in `diary/2026/2026-W33.md`, not into a day file: a day is what happened, a review is
   what somebody made of it.
